    개인정보¶

    cctrace가 수집하는 것, 저장 위치, 조회 권한, 보존 기간.

    서버는 대화 내용을 저장한다

    세션 로그에는 사람이 입력한 내용, 에이전트의 답변, 도구 명령과 출력이 들어 있다. 기본 설정에서는 운영자가 보존 기간을 정할 때까지 계속 보관된다. 다른 사람을 연결하기 전에 보존 기간과 가림 처리를 정해 둔다.

    수집 항목¶

    데이터 보내는 쪽 내용
    OTEL 텔레메트리 에이전트가 직접 OTLP 포트로 메트릭과 이벤트: 토큰 수, 비용, 모델, 도구 활동. cctrace init이 OTEL_RESOURCE_ATTRIBUTES로 사용자 ID, 이름, 이메일, 팀 부착
    세션 로그 동기화 데몬이 /api/sync로 디스크에 기록된 에이전트 세션 파일의 각 줄: 프롬프트, 답변, 추론 텍스트, 인자와 출력을 포함한 도구 호출. 업로드마다 프로젝트 정보(디렉터리 이름, git 원격 URL, 저장소 이름, 브랜치, 커밋) 동봉
    세션 스냅샷과 수집기 heartbeat 동기화 데몬이 /api/session-observations로 Claude Code 세션마다 메타데이터 줄에서 읽은 AI 제목, 사용자 지정 제목, 에이전트 이름, 실행마다의 비용 합계와 추가·삭제 줄 수, 사용한 모델 id, 기록된 PR 링크, 이어서 진행한 세션의 id. 세션이 편집한 파일의 개수와 그중 git status가 아직 커밋되지 않았다고 보고하는 개수, 그 파일들이 속한 저장소 수, git이 자리를 정하지 못한 개수, 개수가 마지막으로 바뀐 시각, 클라이언트가 읽지 못한 편집이 빠졌는지 여부(경로는 보내지 않음). git 호출로 확인한 커밋 식별자와 선택적 제목, 확인하지 못한 호출의 이유(아래 설명). Codex 세션마다 rollout 파일에서 읽은 턴별 id와 상위 턴 id, 시작·끝 시각, 완료인지, 중단(Codex가 남긴 사유와 함께)인지, 오류로 끝났는지(오류 종류와 함께, 오류 메시지는 제외), 소요 시간과 첫 토큰까지 걸린 시간, 모델 컨텍스트 창, 협업 모드, 모델, 추론 강도. 함께 수집기가 실행 중이라는 heartbeat
    실시간 세션 상태와 세션 종료 동기화 데몬이 /api/session-observations로 실행 중인 Claude Code 세션 프로세스마다 Claude Code가 두는 상태 파일(~/.claude/sessions/<pid>.json)에서 약 1분마다 읽은 세션 상태(busy, idle, waiting, shell, 프로세스가 끝나면 gone), 대기 중인 세션이 기다리는 것(input, permission, dialog, sandbox, worker, goal, other), 세션 이름과 그 이름의 출처, 프로세스 id와 시작 시각, 상태가 마지막으로 바뀐 시각, 세션의 프로젝트. 세션이 끝나면 SessionEnd 훅이 알려 주는 종료 사유(clear, logout 등)와 세션의 프로젝트. 프로젝트는 세션의 프로젝트 디렉터리 이름으로, 작업 디렉터리 경로가 그대로 드러남. Windows에서는 Claude Code가 상태 파일에 procStart를 쓰지 않으므로 실시간 상태를 보내지 않음
    규칙 파일 동기화 데몬 세션이 실행된 git 저장소 루트의 CLAUDE.md와 AGENTS.md
    사용 한도 수치 클라이언트 개발자 머신에서 읽은 요금제 사용 한도 현황
    정책 요청 클라이언트가 /api/client-config-policy로 정책을 확인할 때마다 설치 식별자(정책 명령을 처음 실행할 때 cctrace가 ~/.cctrace에 만드는 무작위 UUID)와 프로필 이름을 쿼리 매개변수로 보냄. 토큰은 없음. 서버는 자기 정책 파일로 답하고 요청에서 아무것도 저장하지 않음. 접근 로그에는 메서드, 경로, 상태, 소요 시간, 호출자 주소를 남기고 쿼리는 남기지 않음
    정책 대상 보고 클라이언트가 /api/client-policy-report로 로그인한 프로필은 cctrace config policy apply가 끝날 때마다 실행 결과와 상관없이 한 건: 설치 식별자와 프로필 이름(기본 프로필은 빈 값), 프로필이 올리는 레코드에 붙는 이메일과 사용자 ID, 프로필이 지금 쓰는 서버·OTLP 주소와 OTLP 프로토콜, 마지막으로 적용한 정책 번호, 실행이 끝난 방식(ok, deferred, failed), 실패했거나 보류된 실행이 도달한 정책 번호, 클라이언트 자신의 오류 문구. 오류 문구에는 로컬 파일 경로와 다른 프로필 이름이 들어갈 수 있고 500자에서 잘리며, 프로필의 명시 Codex 홈 경로는 [explicit Codex home]로 바뀜. ok로 끝난 실행도 다음 정책이 올 때까지 문구를 실을 수 있음: 정책이 기본 Codex 설정을 그대로 두면 그 파일의 로컬 절대 경로가, 명시 Codex 홈의 설정을 그대로 두면 경로 없이 explicit Codex home kept가 들어감. 요청 헤더에는 클라이언트 버전, OS, 아키텍처가 더해지며 서버는 버전만 저장
    클라이언트 버전 기록 클라이언트가 /api/sync 업로드마다 계정 이메일마다 사용자 ID, 요청 헤더의 버전·OS·아키텍처, 마지막 동기화 시각, 그리고 보고하는 클라이언트라면 자체 갱신 상태(도달하지 못하는 버전, 연속 실패 횟수, 첫 실패와 마지막 실패 시각, 오류 문구). 오류 문구에는 로컬 파일 경로가 들어갈 수 있고 500자에서 잘림. 계정 제외와 options.collect_repository_prefixes는 이를 막지 않음

    cctrace init은 OTEL_LOG_USER_PROMPTS를 설정하지 않으므로, 사용자가 직접 설정하지 않는 한 Claude Code 자체 텔레메트리에는 프롬프트 텍스트가 없다. 세션 로그에는 어느 경우든 대화 전체가 들어 있다.

    세션 스냅샷은 클라이언트가 그 세션에서 읽은 가장 최근 레코드 시점의 결제 계정에 귀속된다. 세션 도중 계정이 바뀌면 스냅샷 전체가 나중 계정으로 가며, 계정 제외도 그 계정을 기준으로 판단한다. Codex 세션의 스냅샷은 클라이언트가 읽은 가장 최근 턴 줄 시점에 rollout 파일이 있는 Codex 홈에 로그인된 계정에 귀속되며, 그 Codex 홈을 읽는 동기화만 보낸다.

    커밋되지 않은 파일을 세려고 클라이언트는 머신 안에서, 세션이 Edit, Write, MultiEdit, NotebookEdit로 편집한 파일마다 그 위의 가장 가까운 .git으로 속한 저장소를 찾아 git rev-parse로 그 작업 트리 위치를 확인하고, 그곳에서 git status를 실행해 그 파일들만 묻는다. 그 파일 경로는 동기화 상태에 남는다. 세션이 최근 7일 안에 활동한 동안 약 1시간마다 다시 세어 개수가 바뀌면 보내고, 그 7일이 지나면 경로를 지우고 마지막 개수만 남긴다. options.collect_repository_prefixes가 설정되어 있으면 저장소마다 origin을 읽어 판단하고, git status는 수집 대상 저장소에서만 실행하며, 다른 저장소나 저장소 밖의 파일은 세지 않는다. 제외된 계정의 세션에는 git을 실행하지 않는다. Codex 세션에는 이 개수가 없다.

    실시간 상태는 상태를 읽은 시점에 그 Claude 홈에 로그인된 계정에, 세션 종료는 세션이 끝난 시점에 로그인된 계정에 귀속된다. 제외된 계정이나 options.collect_repository_prefixes 밖 저장소의 것은 둘 다 보내지 않는다. SessionEnd 훅이 주는 transcript 경로와 작업 디렉터리는 머신에 남고, 그것이 속한 프로젝트만 보낸다. 세션 종료는 동기화가 보내기 전까지 프로필의 동기화 상태 옆 pending 디렉터리(기본 프로필은 ~/.cctrace/pending/)에서 최대 7일 기다린다.

    Claude Code의 git 호출에는 수집 대상 작업 트리의 HEAD reflog를 최대 2,000개와 현재 브랜치도 읽는다. 해당 호출의 출력 해시로 확인한 생성 후보만 스냅샷에 붙인다. 전체 해시, 커밋 시각, 부모 수, 종류, 저장소, 최근 브랜치, 호출 id, 트랜스크립트 식별자, 확인 근거, amend 전 해시(있을 때), 최대 200바이트 제목이다. 시각이나 제목 일치만으로 확인하지 않는다. 확인하지 못한 호출은 id, 트랜스크립트 식별자, 시각과 이유만 싣는다. 커밋과 미해결 호출은 각각 최대 100개이며 스냅샷 전체 60 KiB 상한을 함께 적용하고 잘린 범위를 표시한다. 명령·출력 원문과 확인하지 않은 후보 제목은 호출 상태에 저장하지 않는다. 대기 중인 호출의 디렉터리와 해시 근거는 로컬에 두고, 7일이 지나면 미해결 이유를 남긴 뒤 지운다. 커밋 조회는 커밋되지 않은 파일 수 조회와 공유하는 flush 5초 중 최대 2.5초를 쓴다. 제외 계정과 저장소의 커밋 제목은 조회하지 않는다.

    정책 요청과 정책 대상 보고는 서명된 서버 정책에 속하며, 업데이트 공개키 또는 정책 공개키를 링크한 클라이언트만 쓸 수 있다. 이 저장소에서 업데이트 공개키도 정책 공개키도 넘기지 않고 빌드한 클라이언트는 빈 공개키를 링크한다(개요 참고). 이런 클라이언트는 백그라운드 정책 확인을 시작하지 않고 정책 요청도 보내지 않는다. cctrace config policy apply는 "policy public key is not configured"로 시작하는 오류로 끝나며, 로그인한 프로필이면 실행할 때마다 그 실패에 대한 보고를 한 건 보낸다. 공개키를 링크한 클라이언트는 감시 프로세스를 시작할 때, 실행되는 동안 약 5분마다, 일회성 cctrace sync가 끝날 때 백그라운드 확인을 하며, 로그인한 프로필의 실행은 매번 보고로 끝난다. 로그인하지 않은 프로필은 보고를 보내지 않으며 cctrace config policy status와 cctrace config policy check도 보내지 않는다.

    저장 위치¶

    수집 데이터는 설정한 서버와 그 TimescaleDB 데이터베이스로 간다. 그 밖의 외부 요청은 다음과 같다.

    • 사용 한도를 읽으려고 클라이언트가 로컬 Claude Code 로그인으로 Anthropic 사용량 API 조회
    • Codex 사용량 가격 산정을 위해 서버가 OpenAI의 공개 가격표와 변경 이력 페이지 다운로드
    • 업데이트 공개키 또는 정책 공개키를 링크한 클라이언트가 받은 정책을 적용하기 전에 시험(cctrace config policy check와 apply): 정책의 새 서버·OTLP 주소로 보내는 짧은 요청이며, OTLP 요청에는 프로필의 업로드 토큰이 담김

    정책 대상 보고는 설치 식별자와 프로필마다 한 행으로 저장된다. 새 보고는 그 행의 값을 바꾸되 처음 확인한 시각은 유지하며, 버전 헤더가 비어 있으면 이전에 저장한 버전을 지우지 않는다. 클라이언트 버전 기록은 계정 이메일마다 한 행이며 동기화할 때마다 갱신된다. 서버는 보고의 형식만 확인하고 사실인지는 확인하지 않는다. 로그인한 클라이언트는 어떤 설치 식별자와 프로필이든 보고할 수 있다. 필드가 잘못되었거나 너무 긴 보고는 HTTP 400으로 거부하고 이유를 로그에 남긴다(운영 참고).

    주간 AI 보고서 기능은 켜져 있으면 설정된 AI 공급자로 데이터를 보낸다. 이 기능은 변경이 진행 중이라 이 문서에서 다루지 않는다.

    엔드포인트가 같은 머신(루프백)이 아닌 곳으로 가는 평문 http://이면 사설 주소라도 클라이언트는 경고만 하고 거부하지 않는다. 직접 관리하지 않는 네트워크로 클라이언트가 접속하기 전에 서버를 TLS 뒤에 둔다. 서버 설치 참고.

    조회 권한¶

    데이터 admin user
    세션 트랜스크립트(/sessions) 모든 사용자 본인
    규칙 파일(/rules) 모든 저장소 본인 세션이 있는 저장소
    집계: 사용량, 비용, 도구, 플러그인·스킬, 사용자별 목록 전체 전체
    텔레메트리 행(/logs) 전체 전체
    사용자 관리, /admin 가능 불가
    • 집계 공유는 의도된 동작. 팀 전체 사용량을 한곳에서 합산하기 위함
    • 텔레메트리 행의 자유 텍스트 속성(프롬프트, 도구 인자와 출력, 명령 텍스트, stdout·stderr)은 관리자 응답을 포함한 모든 대시보드 응답에서 제거. 데이터베이스에는 남아 있을 수 있음
    • user 계정의 본인 세션 판별 기준은 cctrace 사용자 ID. 사용자 ID가 없는 계정은 세션 데이터 조회 불가(CCTRACE_USERID_ACCESS_CONTROL 기본값일 때). 사용자 참고
    • 클라이언트 버전 기록은 관리자에게만 /admin의 Clients 탭에 표시
    • 정책 대상 보고를 읽는 대시보드 페이지나 API는 없음. 데이터베이스에서만 읽을 수 있음

    CCTRACE_USERID_ACCESS_CONTROL¶

    값 user 계정의 세션 매칭 기준
    미설정 또는 false 이외 값(기본값) 계정의 cctrace 사용자 ID
    false 계정의 로그인 이메일과 클라이언트가 업로드에 사용한 이메일

    이 설정은 세션과 소유자를 매칭하는 방식만 바꾼다. 집계를 비공개로 만들지 않는다.

    클라이언트에서 가리기¶

    두 프로필 옵션이 세션 로그가 머신을 떠나기 전에 내용을 지운다. 둘 다 기본값은 꺼져 있다.

    cctrace config set options.redact_user_prompts true
cctrace config set options.redact_tool_details true
    옵션 값을 대체하는 필드
    redact_user_prompts content, text, thinking, summary, title
    redact_tool_details arguments, input, output, result, command, description, stdout, stderr
    • 레코드 안 어디에 있든 해당 필드 값을 [redacted by cctrace client]로 대체. 파싱할 수 없는 줄은 통째로 대체
    • 토큰 수, 비용, 모델, 타임스탬프는 그대로라 대시보드 수치는 변하지 않음
    • 대상은 세션 로그, 세션 스냅샷의 제목, 실시간 상태의 세션 이름. 에이전트가 직접 보내는 OTEL 텔레메트리, 규칙 파일, 정책 대상 보고, 클라이언트 버전 기록은 대상 아님
    • 변경 이후 업로드부터 적용. 서버에 이미 있는 레코드는 가진 값을 유지하며, 재수집이 필드를 더할 수 있음
    • 실행 중인 동기화 데몬은 시작할 때의 옵션을 유지. cctrace sync --stop 후 cctrace sync --daemon으로 재시작

    Claude Code 세션 줄의 일부 내용은 다른 뜻으로도 쓰이는 이름 아래에 있어서, 필드 이름이 아니라 줄 종류와 위치로 찾는다. 이 표의 각 내용은 표에 적은 모든 위치에서 같게 처리한다.

    내용 redact_user_prompts redact_tool_details
    AskUserQuestion으로 물은 질문과 선택지, ExitPlanMode가 제시한 계획(도구 input) 가림 가림
    AskUserQuestion 답변(toolUseResult의 answers와 annotations) 가림 가림
    tool_result 블록 안의 도구 출력(content) 가림 가림
    에이전트가 작업 중일 때 입력한 프롬프트(queued_command 첨부의 prompt) 가림 유지
    백그라운드 작업 결과: 대기열(commandMode가 task-notification인 queued_command)과 별도 user 줄(origin의 종류가 task-notification인 줄의 message의 content) 가림 가림
    계획 파일 내용(plan_file_reference의 planContent) 가림 가림
    계획 파일 경로(plan_file_reference와 plan_mode의 planFilePath) 유지 가림
    작업 제목(task_reminder 첨부의 content) 가림 가림
    Claude Code의 요약(subtype이 away_summary인 system 줄의 content) 가림 가림
    압축 후 이어진 세션이 처음에 싣는 요약(isCompactSummary인 user 줄의 message의 content) 가림 가림
    세션 스냅샷의 확인된 커밋 제목 가림. 둘 중 하나라도 켜진 채 읽은 제목은 옵션을 꺼도 복원하지 않음 가림. 보낼 때의 정책도 다시 적용
    세션 스냅샷의 세션 제목과 에이전트 이름(/api/session-observations) 가림. 옵션이 켜져 있을 때 처음 읽은 제목은 옵션을 끈 뒤에도 가림 유지
    실시간 세션 상태의 세션 이름(/api/session-observations) 가림. 제목과 달리 이름은 1분마다 새로 읽어 보낼 때의 옵션을 따르므로, 옵션을 끄면 세션의 현재 이름이 평문으로 감 유지

    말한 내용이 아니라 일어난 일을 기록하는 필드(프롬프트 ID, 권한 모드, 턴 소요 시간과 개수, 작업 상태, 사용 모델 등)는 가리지 않는다. 세션 스냅샷의 커밋 해시·시각·종류·부모 수·저장소·브랜치·호출 식별자·미해결 이유, PR 링크, 비용과 줄 수 합계, 모델 id, 이어서 진행한 세션 id, 편집한 파일과 커밋되지 않은 파일의 개수, Codex 턴의 시각·끝난 방식과 오류 종류·모델·추론 강도, 실시간 세션의 상태와 기다리는 것, 프로세스 id와 시작 시각, 세션 종료 사유도 어느 옵션으로도 가리지 않는다.

    redact_tool_details만 켜면 일부 도구 출력이 남는다. Claude Code가 이 출력을 도구 필드가 아니라 user 줄의 대화 텍스트로 쓰기 때문이다. 위 규칙보다 먼저 있던 빈틈이며, redact_user_prompts를 켜면 모두 가려진다.

    • SDK 하네스가 텍스트로 쓰는 도구 결과(Tool result (Bash, id=…) 등)
    • ! 셸 명령의 출력(<bash-stdout>)
    • 로컬 슬래시 명령의 출력(<local-command-stdout>)

    이름 있는 프로필에는 --profile <name>을 붙인다. cctrace status가 켜진 가림 처리를 표시한다.

    재수집¶

    cctrace sync reenrich는 세션 파일을 처음부터 다시 읽어, 새 클라이언트가 수집하는 필드를 서버에 이미 있는 레코드에 더한다. 사용자가 직접 입력할 때만 실행된다.

    • 더할 수 있는 필드만 보내며, 대화 본문(message)은 보내지 않음. 기본값은 일어난 일을 기록하는 필드뿐이고, 답변, 대기열 프롬프트와 백그라운드 작업 결과, 계획 파일과 그 경로, 작업 제목, 요약은 머신에 남음
    • --include-content를 붙이면 이것들도 보내고 더하며, 실행 시점의 가림 설정을 따름. 이 필드들을 수집하기 전에 가림을 켠 채 수집한 레코드도 지금 가림이 꺼져 있으면 이 필드들이 평문으로 붙음. 명령은 아무것도 보내기 전에 이를 먼저 알림
    • 레코드에 이미 있는 값은 [redacted by cctrace client] 표식을 포함해 바꾸지 않음. 대화 본문은 더하거나 바꾸지 않음
    • sync가 처음 실행될 때 이미 디스크에 있던 파일 앞부분은 sync가 수집하지 않았으므로 건드리지 않음. sync가 줄어든 것을 발견한 적이 있는 파일은 그때 크기 앞부분도 건드리지 않는데, 이 구간에는 sync가 수집한 줄도 있을 수 있어 그 레코드는 재수집되지 않음
    • 저장소가 options.collect_repository_prefixes 밖이라 sync가 소비만 하고 수집하지 않은 구간과 그 앞부분도 건드리지 않으며, 세션 스냅샷 재구축도 같은 부분을 건너뜀. 부수 효과로, 허용 목록을 좁혔다가 다시 넓히면 좁히기 전에 수집한 줄도 재수집 대상에서 빠짐
    • 같은 구간에서 세션마다 스냅샷(수집 항목)도 만들어, 끝나기 전에 보냄. 기본값에서는 제목과 에이전트 이름을 빼고, --include-content면 실행 시점의 가림 설정으로 함께 보냄. 이 클라이언트가 제목과 함께 보낸 스냅샷을 제목 없는 스냅샷으로 바꾸지 않음
    • Codex 동기화가 켜져 있으면 Codex 세션마다 rollout 파일에서 sync가 수집한 구간으로 턴 목록도 같은 방식으로 만들어 같은 flush에서 보냄

    • 최근 7일 안에 활동한 세션은 같은 구간에서 편집한 파일 목록도 읽어, 커밋되지 않은 파일 수가 이 클라이언트가 읽기 시작한 뒤가 아니라 세션 전체를 다루게 함. 경로는 머신에 남음

    • git 호출도 같은 수집 구간에서 다시 읽되, 최근 7일 제한을 두지 않음. 기본값에서는 확인된 커밋의 제목 키를 빼고, --include-content에서만 현재의 두 가림 정책에 따라 제목을 허용함. 이미 있는 제목이나 가림 표식은 재수집으로 바꾸지 않음

    로컬 분석¶

    cctrace local serve와 cctrace local enable이 켜는 로컬 서비스는 머신에 있는 Claude Code와 Codex 세션 파일을 읽어 동기화 없이 대시보드에 보여 준다. 로컬 분석 참고.

    • 서비스는 루프백 주소에서만 수신하고, 지정하지 않은 출처의 브라우저 요청을 거부하며, 세션 데이터는 토큰이 있는 요청에만 답함
    • 외부로 나가는 요청 없음. 대시보드 페이지가 브라우저에서 쿠키 없이 이 서비스를 직접 읽으므로 이 경로로는 서버에 아무것도 보내지 않음
    • serve는 실행할 때마다 새 토큰을 만들어 한 번 출력함. enable은 토큰을 한 번 출력하고 SHA-256 해시만 ~/.cctrace 아래 프로필 디렉터리에 둠. disable은 그 해시를 버림
    • 연결할 때 "이 탭에 연결 저장"을 고르면 브라우저가 서비스 주소와 토큰을 탭이 닫힐 때까지 sessionStorage에 둠. 대시보드 페이지는 토큰을 페이지 주소, 서버 요청, 로그에 쓰지 않음

    데이터 삭제¶

    대상 권한 방법
    세션 하나 소유자(소유자 삭제 정책이 허용할 때) 또는 관리자 /sessions의 휴지통 아이콘. 페이지 참고
    프로젝트의 세션과 이후 수집 관리자 /sessions의 세션 삭제 대화상자 또는 프로젝트 선택기
    한 계정 이메일로 저장된 텔레메트리, 세션 로그, 실시간 상태, 정책 대상 보고, 클라이언트 버전 기록, 가장 최근 사용 한도 수치, 계정의 세션을 AI 세션 기록(AI가 세션마다 쓰는 개요·검토 사항·작업 상황·태그)에서 가리는 설정(표 아래에 적은 행은 남음) 관리자 /users의 Clear Collected Data. 사용자 참고

    삭제한 세션은 클라이언트가 다시 올려도 거부된다.

    계정을 병합하면 계정의 정책 대상 보고와 클라이언트 버전 기록은 병합 대상 계정으로 옮겨진다. 두 계정 모두 클라이언트 버전 기록이 있으면 동기화가 기록을 갱신할 때처럼 합친다. 마지막으로 동기화한 기록이 우선하되, 그 기록에 버전, OS, 아키텍처, 자체 갱신 상태가 없으면 다른 기록의 값을 남긴다. 계정의 세션을 AI 세션 기록에서 가리는 설정도 옮겨지고, 병합 대상 계정은 이를 자기 설정으로 본다. cctrace 사용자 ID로 저장된 설정은 그 자리에 두고 그 ID로 계속 적용한다. 병합 대상에 같은 설정이 이미 있으면 대상의 설정이 남는다. 계정 전체를 가리는 설정이 옮겨지면 병합 대상 계정 자신의 세션도 함께 가려진다. 계정의 가장 최근 사용 한도 수치는 옮기지 않고 지운다. 병합 대상 계정 자신의 보고가 그 수치를 계속 채운다.

    Clear Collected Data는 계정의 세션을 AI 세션 기록에서 가리는 설정도 지운다. 그 뒤 계정에서 수집되는 세션은 /api/privacy로 설정을 다시 만들기 전까지 AI 세션 기록에서 가려지지 않는다.

    Clear Collected Data도 계정 병합도 계정 이메일을 작성자로 기록한 규칙 파일 버전은 지우지 않는다. 계정의 사용 한도 수치 이력(quota_samples)과 거기서 파생된 제외 주소 목록, 계정이 들어간 48시간보다 오래된 시간별 사용량 집계도 지우거나 옮기지 않는다. 그 행은 운영자가 데이터베이스에서 지울 때까지 남을 수 있다.

    병합하면 두 프로필은 가장 최근 사용 한도 수치 하나를 함께 쓴다. 두 프로필이 서로 다른 Claude 계정에 로그인되어 있었다면 이후 보고가 병합 대상 주소로 저장되면서 서로의 값을 번갈아 덮어쓴다. 사용 한도 수치의 이력은 병합을 따라가지 않고, 각 수치에는 보고한 프로필의 이름이 그대로 남는다.

    보존 기간¶

    테이블 내용 기본값
    otel_events 텔레메트리 이벤트 90일 후 삭제, 30일 후 압축
    otel_metrics 텔레메트리 메트릭 90일 후 삭제, 30일 후 압축
    session_records 세션 로그(대화 내용) 정책 없음: 운영자가 정할 때까지 보관
    client_policy_reports 정책 대상 보고 보존 설정 대상 아님: Clear Collected Data나 운영자가 행을 지울 때까지 보관
    client_versions 클라이언트 버전 기록 보존 설정 대상 아님: Clear Collected Data나 운영자가 행을 지울 때까지 보관

    session_records에 정책이 없으면 서버는 시작할 때 다음을 기록한다.

    [cctraced] notice: session_records (conversation content) has no retention policy and is kept indefinitely, while otel_events/otel_metrics are dropped after 90 days. Set SESSION_RETENTION_DAYS (0 = keep forever) or choose an interval in Admin -> Storage.

    보존 기간은 /admin의 Storage 탭에서 설정한다. cctraced는 SESSION_RETENTION_DAYS, OTEL_RETENTION_DAYS도 읽지만 기본 제공 compose 파일은 이 둘을 컨테이너에 전달하지 않는다(서버 설정). 컨테이너에 전달되면 환경 변수 값이 우선하며 대시보드의 해당 설정을 잠근다. 기간을 줄이면 기존 데이터가 삭제된다. 자세한 내용: 운영.
